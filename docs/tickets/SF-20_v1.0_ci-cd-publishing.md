# SF-20: CI/CD, Code Coverage & Publishing

**Module:** Root (GitHub Actions)
**Depends on:** SF-01
**Milestone:** v1.0
**Spec Reference:** [TECH_SPEC.md](../TECH_SPEC.md) &sect;18.5 (CI/CD)

## Goal

Create GitHub Actions workflows for CI, code coverage reporting, snapshots, and releases.

The repository should automatically build, test, generate JaCoCo coverage reports, publish coverage/build badges in the README, publish snapshots on merge to `main`, and support manual signed releases to Maven Central.

## Requirements

1. **CI** (`.github/workflows/ci.yml`)

   - Run on push and pull requests.
   - Build the project.
   - Run unit tests.
   - Generate JaCoCo code coverage reports.
   - Cache Gradle dependencies.
   - Upload test reports.
   - Upload JaCoCo HTML coverage reports.
   - Fail the workflow if build or tests fail.
   - Optionally run coverage verification if a minimum threshold is configured.

2. **Code Coverage**
   - Configure JaCoCo in Gradle if not already configured.
   - Generate XML and HTML reports.
   - Ensure the XML report is available for CI parsing.
   - Ensure the HTML report is uploaded as a workflow artifact.
   - Provide a command that works locally:

```bash
   ./gradlew clean test jacocoTestReport
```

- Expected report locations:

```text
build/reports/jacoco/test/jacocoTestReport.xml
build/reports/jacoco/test/html/index.html
```

- For multi-module builds, provide either:

  - an aggregate JaCoCo report, or
  - clearly documented per-module coverage reports.

3. **README Badges**

   - Add a GitHub Actions build status badge to `README.md`.
   - Add a coverage percentage badge to `README.md`.
   - Coverage badge should be based on the JaCoCo XML report generated in CI.
   - Use a Shields.io-compatible endpoint badge, for example:

   ```markdown
   ![Build](https://github.com/OWNER/REPO/actions/workflows/ci.yml/badge.svg)
   ![Coverage](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/OWNER/REPO/main/.github/badges/jacoco.json)
   ```

   - Replace `OWNER`, `REPO`, and `main` with the actual repository details.

4. **Coverage Badge JSON**

   - Generate or update:

   ```text
   .github/badges/jacoco.json
   ```

   - Badge JSON should follow the Shields.io endpoint format:

   ```json
   {
     "schemaVersion": 1,
     "label": "coverage",
     "message": "82.45%",
     "color": "brightgreen"
   }
   ```

   - Calculate coverage using JaCoCo instruction coverage:

   ```text
   coverage = covered / (missed + covered) * 100
   ```

   - Use these badge colors:

     - `>= 80%`: `brightgreen`
     - `>= 70%`: `yellowgreen`
     - `>= 60%`: `yellow`
     - `< 60%`: `red`

   - Commit badge JSON updates only on pushes to the default branch.

   - Do not update badge JSON from pull request workflows.

5. **Snapshot** (`.github/workflows/snapshot.yml`)

   - Run after merge to `main`.
   - Build and test the project before publishing.
   - Publish snapshot artifacts to GitHub Packages.
   - Publish snapshot artifacts to Sonatype Snapshots.
   - Use GitHub Actions secrets for credentials.
   - Do not publish snapshots from pull requests.

6. **Release** (`.github/workflows/release.yml`)

   - Manual trigger via `workflow_dispatch`.
   - Strip `SNAPSHOT` from the release version.
   - Build and test before publishing.
   - Generate coverage as part of the release validation.
   - Sign artifacts.
   - Publish to Maven Central.
   - Create and push a Git tag.
   - Bump the project version after release.
   - Use GitHub Actions secrets for signing and publishing credentials.

7. **Artifacts**

   - CI should upload:

     - Gradle test reports
     - JaCoCo HTML coverage reports
     - Any relevant build reports

8. **Documentation**

   - Update `README.md` or `CONTRIBUTING.md` with:

     - How to run CI-equivalent checks locally.
     - How to generate coverage locally.
     - Where to find coverage reports.
     - What the README badges mean.
     - How snapshots and releases are triggered.

## Acceptance Criteria

- CI runs on PRs.
- CI runs on pushes.
- CI builds the project successfully.
- CI runs tests successfully.
- CI generates JaCoCo XML and HTML reports.
- CI uploads test reports as artifacts.
- CI uploads JaCoCo HTML reports as artifacts.
- README includes a build status badge.
- README includes a live coverage percentage badge.
- `.github/badges/jacoco.json` is generated or updated on push to the default branch.
- Coverage badge is not updated from pull request workflows.
- Snapshots publish on merge to `main`.
- Release workflow signs, publishes, tags, and bumps version.
- Local command works:

```bash
./gradlew clean test jacocoTestReport
```

- Local verification works:

```bash
./gradlew clean check
```

## Implementation Notes

- Prefer the existing Gradle DSL style: `build.gradle` or `build.gradle.kts`.
- Do not introduce Codecov, Coveralls, SonarCloud, or other external coverage services.
- Use JaCoCo as the source of truth for coverage.
- Use GitHub Actions built-in artifacts for reports.
- Use Shields.io endpoint badge JSON for the coverage badge.
- For multi-module projects, prefer aggregate JaCoCo coverage if practical.
- Keep release and snapshot workflows separate from CI.
- Ensure publishing credentials and signing keys are read from GitHub Actions secrets.
